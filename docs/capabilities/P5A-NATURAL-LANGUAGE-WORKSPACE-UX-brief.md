# P5A 自然语言优先的对话与 Work Mode 体验

- 阶段：Program Phase II / P5A UX 成熟化
- 状态：已获项目负责人批准；等待实现任务协议
- 设计基线：P1 `Scope -> Tool -> ViewContext -> Workspace`，P2 Fixture 光模块健康能力
- 视觉参考：项目负责人于 2026-07-27 提供的四张 AskLily 概念图；参考图不作为真实数据、功能完成或外部素材授权的证据。

## 用户价值

维护人员应先用自然语言提出宽泛问题，先获得可追溯的粗粒度结论；若仍不满意，可以顺着对话逐步追问。系统在模型判断结构化数据更适合调查时自动展开 Work Mode，展示已注册模块的查询结果，而不要求用户学习复杂查询语法或手动选择页面模式。

## 交互决定

### 对话模式

- 用户问题使用气泡展示；助手以文章式、可阅读的结论展开，必须保留来源、时间、限制和失败说明。
- 富文本结论可以解释结构化事实，但图表、表格、告警列表和任何业务数据只能来自已查询的结构化模块结果，不能从自然语言正文解析或由模型捏造。
- 首次宽泛提问默认允许先返回粗粒度摘要和可继续追问的方向；这不是前端强制流程，模型可在合法响应中直接请求 Work Mode。
- 生产界面不提供 Chat/Work 的手动切换入口；用户始终可在 Work Mode 左侧继续对话。

### Work Mode

- 是否进入由模型通过受约束的展示指令决定，程序不根据问题长度、记录数量或前端启发式规则自行决定。
- 前端收到合法 `work` 指令后，将会话区域以动画移动到左侧约三分之一；工具区域收缩至最左窄栏；右侧按返回顺序渲染模块。
- 模型只能请求注册过的模块，后端负责验证每个 ViewContext、授权 Tool、执行查询和返回结构化结果。模型不能返回任意 HTML、图表定义、SQL、外部地址或未注册模块。
- 模块的视觉组件、字段、空/加载/错误状态和默认尺寸由 View Registry/前端模块拥有；模型只选择模块与已公开的筛选条件。

### 开发调试

在尚未接入模型的 Developer Profile，可提供清晰标记的调试按钮以强制模拟 `chat` 或 `work` 展示。它只能使用固定 Fixture 与合法预置 ViewContext，不得出现在 Standalone/正式界面，也不得绕过 Scope、Tool 或后端校验。

### 空会话首页

- 左侧展示“新建对话”和账号最近对话；账号历史依赖 [ADR-0004](../adr/0004-local-account-and-conversation-history.md) 的 P5B 交付。
- 主区域在两种视觉状态间粒子聚散：抽象 Lily 女性半身品牌形象，以及由固定 Fixture 产生的待关注自然语言问题。
- 待机时，整个右侧对话区是粒子画布；标题、调试信息和输入框仅悬浮其上，不得再以居中的内层卡片承载粒子视觉。
- 桌面端以应用底板承托左侧会话卡、对话卡和 Work Mode 工作卡；三者共用间距、圆角、描边和投影，切换 Work Mode 时不得出现贴边分割的突兀界面。
- Developer 调试切换与未来受验证的 `work` 展示指令均使用同一条 3 秒布局过渡：左侧卡收窄为工具栏、对话卡左移并收缩、右侧工作卡展开，模块内容在展开后段淡入。
- 每轮只展示一条待关注问题；女性形态与问题形态之间的散开、聚合过渡为 2 秒，其余时间保持对应形态。
- 点击待关注问题后立即发送该预设问题。调试期必须显示其 Fixture/L0-L1 性质；不得称为真实预测、真实告警或真实系统待办。
- 通知、账号、设置和工作模式图标在首版仅为视觉占位，不实现业务入口。
- 动画必须尊重 `prefers-reduced-motion`，并提供静态背景和无动画可读文本的降级；视觉效果不得遮挡输入、问题卡或错误信息。

## 展示指令接口（提案）

该接口是模型 Skill 与平台之间的受限展示契约，不是模型直接控制浏览器的通道。它以现有单一 `ViewContext` 为基础，新增可选、非破坏性的有序集合：

```json
{
  "presentation": {
    "mode": "work",
    "modules": [
      {
        "view_context": {
          "view_id": "optic_health",
          "version": "1.0.0",
          "scope": { "project_id": "demo-project", "site_ids": ["site-a"], "actions": ["read"] },
          "filters": { "health": ["critical"] },
          "focus_resource_id": "optic-a-02",
          "query_id": "server-issued-query-id"
        }
      }
    ]
  }
}
```

规则：

1. `mode` 仅为 `chat` 或 `work`。`chat` 不带 `modules`；`work` 带一个或多个模块，前端严格按数组顺序渲染。
2. 每一项必须包含独立、已注册的 `view_id` 与 View Contract 允许的筛选字段。`scope` 由服务端重新收窄，`query_id` 仅能由服务端签发。
3. 模型/Skill 只产生候选展示请求；后端验证失败时返回结构化拒绝或模块错误，不能静默转成未校验的页面数据。
4. API 返回的模块结果必须携带来源、时间、数据等级和限制。前端不能因工作模式而隐藏 Fixture、严格只读或非 Production 提示。

最终字段名、OpenAPI/Pydantic 类型和单模块兼容策略必须由 P5A 任务协议冻结；若会破坏现有 `ViewContext` 1.0.0，先建立 ADR。

## 范围

- 自然语言优先的会话壳、文章式回答、输入框、最近对话区域和 Work Mode 动画布局。
- 有序多模块展示指令的前后端适配、已注册模块渲染器以及合法 ViewContext 校验。
- 开发期的 Fixture 调试切换、空会话粒子视觉和可点击的固定 Fixture 问题。
- 加载、空数据、拒绝和数据源失败状态；键盘可用性、窄屏布局与减少动态效果降级。

## 非目标

- 不接入真实模型 Provider、真实 Zabbix、真实数据、写操作、自动修复、工单或预测能力。
- 不允许模型直接查询 Connector、直接持有 Scope、生成任意页面结构或绕过 View/Tool Registry。
- 不实现通知、设置、账号管理、SSO 或真实历史；账号与历史由 P5B 独立交付。
- 不把概念图中的 PUE、工单、预测设备、拓扑等内容当作已有业务能力或 Fixture 事实。

## 依赖与顺序

1. P5B 本地账号与对话历史先建立受控的服务端身份和持久化边界；P5A 可在开发期使用临时 Fixture 壳进行视觉验证，但不得伪称真实历史已完成。
2. P5A 冻结展示指令与多模块校验后，任何业务模块才能被模型 Skill 请求。
3. 每个新的 `view_id` 仍须以独立 Capability Brief、Fixture/Scenario、Tool、View、E2E 和完成包交付。

## 验收

- 实际浏览器中，宽泛问题可显示文章式 Fixture 结论并保留来源、时间、限制；用户可继续追问。
- 合法 `work` 指令触发会话平移动画，并按返回顺序渲染多个已注册模块；不存在生产手动模式切换。
- 未注册模块、Scope 扩张、非法 filters、伪造 query ID 或模块查询失败均有可见、安全的失败状态，且不泄露越权数据。
- Developer Profile 的调试切换只使用 Fixture；Standalone 不显示该入口。
- 空会话问题点击后立即发送；粒子视觉在减少动态效果设置下退化为静态、可读状态。
- 浏览器 E2E 覆盖 Chat、自动 Work Mode、连续追问、多个模块顺序、错误/空态、operator Scope 与窄屏/键盘路径；既有契约/API/E2E 回归必须继续通过。

## 风险

- 多模块响应会扩展展示契约，必须先做兼容性审查，不能以 UI 改造名义绕开版本化契约。
- 当前系统无模型、真实历史或通用模块库；早期所有演示必须显式限于 Fixture/L0-L1。
- 粒子动画和大面积视觉背景可能损害性能或可访问性，因此减少动态效果与静态降级是验收项，不是可选美化。
